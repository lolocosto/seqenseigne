## Sujet immédiat — v0.13.4

### Périmètre

Refonte des sidebars des **4 ateliers d'atomes** (Notions, Méthodes,
Fiches de résumé, Exercices) pour répliquer le rendu visuel de la
sidebar de l'atelier d'assemblage (`atelier_seqniv_assemblage.js`).

### Règles de rendu — décidées avec Laurent

#### Notions / Méthodes / Fiches de résumé

- Items au format `.asm-item` (carte compacte avec bordure visible
  `1px solid var(--border)`, background `var(--surface)`, `border-radius
  small`, padding `6px 8px`)
- **Pas de badge** de type (un seul type par atelier)
- **Pas de bouton ✎ Éditer** (le clic sur la ligne suffit, on est déjà
  dans l'atelier dédié — différent de la sidebar d'assemblage où le ✎
  servait à sauter vers un autre atelier)
- **Pastille ronde** d'état d'édition (verte = validé, grise = en
  cours), à la place du `atome-etat-badge` actuel
- **Pas de sections repliables** (la sidebar reste plate, comme aujourd'hui)
- **Filtre par état conservé** (boutons Tous/En cours/Validé)

#### Exercices

- Items au format `.asm-item` (idem)
- **Sections repliables** par série (F, A, E, EA, R) avec en-tête
  cliquable + count à droite (style `.asm-cat-head` / `.asm-cat-count`)
- **Badge** par série (F/A/E/EA/R) avec les couleurs définies dans
  `app.css` (`asm-item-badge--F` / `--A` / `--E` / `--EA` / `--R`)
- **SUPPRESSION du filtre par série** actuel (boutons « Tous /
  Fond. / Avancé / Explor. / Approche ») → remplacé par les sections
  repliables
- **Conservation** du filtre par état (Tous/En cours/Validé)
- **Pastille ronde** d'état d'édition (idem N/M/F)
- **Pas de bouton ✎ Éditer** (idem)

## Points d'attention pour la prochaine session

### Couplage paquet ↔ Python

Depuis la v0.13.2, certaines livraisons modifient à la fois le paquet
LaTeX (`.dtx`/`.sty`) et le code Python. Procédure de déploiement
toujours :
1. **Paquet d'abord** : copier `seqenseigne-theme.sty` dans MiKTeX
   (option simple) ou lancer `make install` (option propre).
2. **Application Python ensuite** : décompresser le ZIP.

La **v0.13.4 ne touche pas le paquet LaTeX** donc cette précaution
n'est pas nécessaire pour la prochaine livraison.

### Tests

Aucun test pytest ne lance pdflatex sur le LaTeX généré. Les régressions
de compilation sont détectées **par toi** au moment du déploiement.
C'est un point de vigilance connu, à considérer pour la roadmap (par
exemple un test d'intégration qui compile un livret simple).

### Cohérence CSV ↔ BDD pour les prérequis

Le fallback CSV de la v0.13.3 lit `data/CXX_objectifs.csv` quand la
séquence prérequise est absente de la BDD applicative. Attention : si
tu peuples N09 dans la BDD applicative un jour, le chemin BDD
prendra le pas sur le CSV (par construction du fallback). Pour
l'instant, c'est exclusivement le CSV qui sert pour N07/N08/N09.

### Conventions du projet (rappel)

- Delivery format : un ZIP par livraison, avec `redemarrage_*.md` dans
  `appli/doc/`
- `Complete file replacement only` : pas de patches/diffs, fichiers
  complets uniquement
- Tone : warm but technical, sans emoji sauf milestones
- Sanity check final : copie fraîche `appli.zip`, empiler tous les ZIPs
  dans l'ordre, pytest
